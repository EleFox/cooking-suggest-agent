# Raw Ideas

## User Original Description

（2026-08-14 记录）

我想设计一款应用，它的目的是为了解决普通家庭每天做菜时，确定"今天吃什么"这个问题。

对于这个问题，我的解决方法是，让用户可以勾选食材白名单、料理手段白名单、花费时间区间，以及配合营养学、时令季节、价格波动来匹配对应的菜谱输出对应的内容。

高级内容甚至可以用户直接口述需求后立马生成对应的菜谱。

## Extracted Facts

- 目标用户：普通家庭
- 核心问题：每天做菜时确定"今天吃什么"
- 输入条件（用户可勾选）：
  - 食材白名单
  - 料理手段白名单
  - 花费时间区间
- 匹配逻辑：结合营养学、时令季节、价格波动
- 输出：匹配对应的菜谱
- 高级能力（IDEA）：用户口述需求后立马生成菜谱

## Ideas

- 口述需求 → 立即生成菜谱（语音交互，可能是高阶功能）
- 在食材白名单、料理手段白名单、时间区间之外，匹配营养 / 时令 / 价格

## Assumptions

- 用户有"营养、时令、价格"这三个维度的偏好或需要
- 用户愿意每天先勾选/输入条件再去获得菜谱（使用前成本较高）
- "确定今天吃什么"是真正的痛点，且值得专门做一个应用
- 普通家庭现在没有一个可接受的解决方案
