# Problem / WHY

## 为什么要做这件事（用户原话摘录）

（2026-08-14 记录）

"目前我自己遇到最大的痛点在于，不同家庭成员（尤其是自己）对于很多菜品存在禁忌，以及在每天的料理过程中，脑子里的菜谱很少，导致经常出现菜谱的重复，导致实际上每天吃的都是差不多的内容以及灵机一动的鬼点子，如果单纯从网上获取灵感，会遇到对应的食材或者调料没有或者存在禁忌的情况，所以有个应用能够把自己能想到的在各种层面的饮食需求加进去，并获得最终的推荐菜单。"

## 识别出的问题点

1. **禁忌约束**（FACT）
   - 不同家庭成员各有饮食禁忌（尤其是用户自己）
   - 禁忌导致很多菜品天然不可选

2. **菜谱库存少 → 重复**（FACT）
   - 用户脑子里可做的菜谱数量少
   - 导致菜单重复、每天吃的差不多

3. **"灵机一动的鬼点子"**（FACT）
   - 在重复之外，用户有时靠临时想到的点子做饭
   - 鬼点子 = 缺乏结构化的新想法时的补偿手段

4. **网上灵感不可行**（FACT）
   - 网上看到的菜谱，常遇到：食材/调料家里没有，或触犯禁忌
   - 外部灵感与"家里实际条件"脱节

## 用户期望的解决方向

- 一个应用，能把自己能想到的**各种层面的饮食需求**加进去
- 基于这些需求，获得**最终的推荐菜单**

## 关键洞察（AI 推断，待验证）

- 用户的真实需求更像是一个**"约束求解器"**：在禁忌、家里现有食材、时间等约束内，找到"能做的、且不重复的"菜。
- 痛点不只是"决策成本"，还有"决策正确性"——推荐必须落在约束内才可用。
- "网上找灵感"失败的本质：**外部菜谱与家庭约束（禁忌 + 现有食材调料）不匹配**。

## 需求提炼（v2，2026-08-14）

### 用户补充

- **健康与营养**是原始需求中遗漏的关键因素（FACT）
- 在"重复"与"新菜谱不可行"之间，更偏向"重复"，但都不贴切（FACT）
- 正确想法：考虑做什么料理时，应用通过**偏好、料理时间、健康、应季**等多重因素，给出一个良好的答案（FACT）
- 平时做菜，如果为一顿饭去逐项调查各种东西，明显不现实（FACT）
- "灵机一动改菜谱"推迟：初版不考虑；未来版本可能涉及应用提供改菜谱建议（CONFIRMED - 延后）

### 提炼后的核心问题

做菜决策（决定"今天做什么"）是一件需要**同时权衡多重因素**的事：

- 家庭成员偏好与禁忌
- 当天可支配的料理时间
- 营养健康
- 时令季节
- ~~食材可得性（家里现有食材调料）~~ → 已从核心因素中移除（DEC-002，转为未来扩展）

人脑无法在每顿饭前快速完成这种**多因素权衡**：

- 于是只能依赖少量记忆菜谱 → 重复
- 或者放弃综合考量 → 不健康、不应季、不均衡

### 提炼后的核心价值（v2）

把"多因素权衡"这件事**封装成一次决策**：用户不需要逐项查资料，应用综合偏好、时间、健康、应季等因素，直接给出"约束内且综合表现良好"的菜谱答案。

### 关键洞察（更新）

- 核心痛点不是"缺灵感"，而是"**多因素权衡的手工成本太高**"
- "重复"是权衡成本过高的症状，不是问题本身
- 应用定位：一个**多因素决策器**，而非灵感推荐器

## 健康营养维度（补充确认，2026-08-14）

- 用户确认：**多因素决策器** 定位正确（CONFIRMED）
- 健康营养：用户"需要做但缺乏相关知识"（FACT）
- 期望：应用把**专业知识**吸纳进去，并**影响决策**，提升料理健康度（CONFIRMED）
- 含义：健康不是用户自己能评估的选项，而是应用必须替用户把关的"专家维度"
