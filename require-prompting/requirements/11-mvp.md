# MVP

## 核心假设（待验证）

"用户把家庭偏好配置好后，点一下就能拿到一份全家能吃、倾向的菜谱，决策纠结显著降低。"

## MVP 建议范围（最小验证闭环）

1. **成员偏好**：可选，人数可为 0；有成员时支持偏好 + 禁忌
   - 决策引擎需兼容"无成员偏好"（仅凭料理偏好等因素决策）
2. **料理偏好**：料理手段 + 料理时间（决策前勾选）
3. **决策引擎**：禁忌硬过滤 + 偏好软排序（权重用默认值即可）
4. **即时生成**：一次生成 1 道菜
5. **再来一个**：追加生成新菜，不与已有重复
6. **固定格式展示**：统一字段呈现
7. **最小菜谱池**：内置少量预标注菜谱（够支撑日常验证即可）

## 候选剔除项（讨论是否排除出 MVP）

| 项 | 建议 |
|----|------|
| 权重设置页（US-06） | 正式功能，但 MVP 可用默认权重先跑通闭环？ |
| 自由文本输入（US-05） | 可延后？ |
| 方案缓存（US-04） | 便利性，可延后？ |
| 手动新增菜谱（US-11） | 可延后？ |
| 时令知识（REQ-08） | 可延后？ |
| 健康营养（REQ-08） | 明确往后 |
| 餐次规划、黑白名单、使用记录 | 已 P2，排除 |

## MVP 验证点

- 是否显著降低决策纠结（核心）
- 禁忌是否 100% 不撞
- 生成结果是否"能吃且倾向"（默认权重下）
- 追加生成是否有效缓解"不满意"
