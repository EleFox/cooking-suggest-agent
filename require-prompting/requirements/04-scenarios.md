# Scenarios / WHEN & WHERE

## 场景描述

（2026-08-14 记录）

存在两种使用模式（FACT）：

### 模式 A：菜单规划（计划性）
- 可按**一周或两周**建立菜谱规划
- 用户一次性确定要规划的**餐点时间**（例如：勾选周一晚饭、周三晚饭、周日早中晚）
- 非固定全天连续，而是**按需勾选**餐次

### 模式 B：即时生成（即时性）
- 用户随时**立马生成一个菜谱**
- 不满意可以**刷新**，重新获得菜谱（迭代循环）

## 场景要素

| 要素 | 内容 |
|------|------|
| WHEN | 提前规划（一周/两周）或做饭前即时 |
| TRIGGER | 需要决定"做什么菜" |
| GOAL | 获得约束内、综合良好的菜谱/规划 |
| PAIN | 手工多因素权衡成本高 |
| OUTCOME | 可执行的菜谱 或 一/两周的餐次规划 |
| 循环 | 不满意 → 刷新 → 重新生成（CONFIRMED） |

## 关键张力（AI 推断，待确认）

- 规划模式（未来餐次）与"家里现有食材"因素存在时间错位：
  - 即时生成时，食材 = 现在家里有的
  - 一周规划时，未来几天的食材还没买
  - 待确认：规划模式是否还考虑"现有食材"，还是只基于偏好/禁忌/时间/健康

## 澄清（2026-08-14，CONFIRMED）

- **食材管理不纳入本次系统需求**：家庭层面不需要严格的食材管理
- 菜单性质 = **弹性参考**，不是严格执行的规则（应用是参考意义）
- 未来扩展：用户明确指定菜谱使用哪些食材，并提供两种模式：
  - 只使用这些食材
  - 允许加入其它食材
