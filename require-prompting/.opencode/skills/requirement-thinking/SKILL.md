# Requirement Thinking Skill

## Purpose

帮助用户把模糊 IDEA 转化为结构化需求。

不是直接生成 PRD。

而是通过：

观察
→ 提问
→ 总结
→ 分类
→ 验证
→ 收敛

逐步形成需求。

---

# Phase 1 Raw Idea

目标：

获取用户原始想法。

必须：

- 保留原话
- 提取概念
- 区分 IDEA / FACT / ASSUMPTION
- 不评价

问题：

"你现在脑子里想做什么？"

---

# Phase 2 Problem

目标：

找到真正的问题。

依次考虑：

WHY？

为什么做？

当前问题是什么？

用户现在怎么解决？

哪里不满意？

不要讨论技术。

---

# Phase 3 Users

目标：

找到真正的用户。

问题：

WHO？

谁会使用？

谁最需要？

不同用户有什么区别？

---

# Phase 4 Scenario

目标：

理解用户什么时候遇到问题。

模板：

WHEN？
WHERE？
TRIGGER？
GOAL？
PAIN？
OUTCOME？

---

# Phase 5 Value

目标：

区分：

Feature
Need
Value

例如：

"AI 自动生成答案"

不是最终价值。

继续追问：

"为什么需要答案？"

直到得到用户真正想获得的结果。

---

# Phase 6 Experience

建立用户旅程：

Trigger
→ Action
→ Response
→ Decision
→ Outcome

不要设计 UI。

---

# Phase 7 Capability

从用户体验反推：

系统需要具备什么能力？

不要讨论具体技术。

---

# Phase 8 Requirement

把能力拆成：

- 可理解
- 可讨论
- 可验证
- 尽可能独立

的需求。

---

# Phase 9 User Story

模板：

作为 [用户]
我希望 [行为]
以便 [价值]

必须能够回答：

WHO
WHAT
WHY

---

# Phase 10 Acceptance

使用：

Given
When
Then

避免模糊词。

---

# Phase 11 MVP

寻找：

"最小的能够验证核心假设的用户体验。"

不要追求完整产品。

---

# Phase 12 Complete

检查：

- Problem
- User
- Scenario
- Value
- Experience
- Capability
- Requirement
- User Story
- Acceptance
- MVP

是否已经基本明确。

未解决问题可以存在。

不要求 100% 确定。

---

# Conversation Rules

每次：

1. 读取上下文
2. 判断阶段
3. 简短总结
4. 找一个最大未知点
5. 提一个问题
6. 等待

最多两个问题。

不要长篇教学。

---

# Thinking Rules

永远区分：

用户说的
AI 推断的
AI 建议的

推荐输出：

"你刚才说的是……"

"我理解成……"

"这里我有一个假设……"

"这里还有一个问题……"

不要把 AI 推断写成事实。
