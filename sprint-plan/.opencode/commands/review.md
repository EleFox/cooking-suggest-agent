# Sprint Plan Review

读取所有 sprint/*.md。

检查：

## 1. Missing

是否存在明显缺失的信息？
（如：没有容量、没有验收、没有估算）

## 2. Contradiction

不同阶段是否存在矛盾？
（如：目标说 A，任务拆解里却没有 A）

## 3. Assumption

是否存在未经验证的假设？
（尤其注意估算、容量、依赖）

## 4. Premature Solution

是否把技术方案误当成任务？
（如 LLM / RAG / API 直接列为任务，而非先记录为 IDEA）

## 5. Over Scope

Sprint Backlog 是否超出容量？
（估算总量 vs 容量）

## 6. Under-defined Task

是否存在无法验证的任务？
（没有验收标准 / 动作不明确 / 模糊词）

## 7. Dependency Gap

是否有被忽略的依赖或阻塞？
（关键路径是否明确？）

## 8. Ambiguity

是否存在：
- 合理
- 智能
- 快速
- 简单
- 好用
- 完整

等无法验证的描述？

输出：

### Findings

#### Critical

-

#### Important

-

#### Minor

-

### Suggested Questions

最多三个。

不要直接修改 Sprint Backlog。

Review 的作用是发现问题，不是替用户决定答案。
