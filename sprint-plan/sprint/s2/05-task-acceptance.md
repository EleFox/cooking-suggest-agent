# Task Acceptance / 任务验收标准（DRAFT，2026-09-05）

> 每个任务定义 Given/When/Then 验收标准。验收标准先于承诺。

## T1 · 料理偏好设置页

### AC-T1-1 勾选偏好并进入结果页

- Given 用户进入料理偏好设置页（独立路由）
- When 勾选料理手段与料理时间偏好，点击确认
- Then 进入菜谱结果页，且偏好作为决策输入传入接口

### AC-T1-2 0 成员情况

- Given 设置页无成员数据（0 成员）
- When 用户正常勾选偏好并确认
- Then 无成员区阻塞或报错，流程正常

### AC-T1-3 不自动应用默认方案

- Given 已存在标记为默认的方案
- When 用户重新进入设置页
- Then 勾选项不自动填充默认方案，由用户手动勾选或调出方案

## T2 · 料理偏好方案缓存

### AC-T2-1 新建方案

- Given 用户已勾选一组偏好组合
- When 用户输入方案名并保存
- Then 方案持久化到后端，出现在方案列表中

### AC-T2-2 调出方案

- Given 方案列表中存在某方案
- When 用户点击调出该方案
- Then 方案中的偏好勾选自动填充，无需重新勾选

### AC-T2-3 编辑方案

- Given 存在某方案
- When 用户修改方案名称或勾选项并保存
- Then 方案更新生效并持久化

### AC-T2-4 删除方案

- Given 存在某方案
- When 用户删除该方案
- Then 方案从列表移除，且持久化删除

### AC-T2-5 默认方案标记

- Given 存在多个方案
- When 用户标记某方案为默认 / 取消默认
- Then 默认标记生效并持久化

## T3 · 对接料理决策接口

### AC-T3-1 偏好传入决策接口

- Given 用户在设置页确认偏好
- When 进入结果页并发起生成
- Then 决策请求携带当前偏好 elements（替换硬编码参数）

### AC-T3-2 沿用既有决策链路

- Given 决策接口已有实现
- When 前端传入偏好参数
- Then 决策接口按已有逻辑处理，返回菜谱结果

### AC-T3-3 硬编码参数移除

- Given 前端原使用硬编码决策参数
- When 本轮对接完成后
- Then 硬编码参数不再作为决策输入来源
