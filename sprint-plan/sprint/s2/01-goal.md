# Sprint Goal / 迭代目标（CONFIRMED，2026-09-05）

## 一句话目标

提供独立的料理偏好设置页，支持勾选料理手段/时间、保存与调出偏好方案（完整 CRUD + 默认方案），并将当前勾选偏好传入已有决策接口，完成"设置 → 生成"闭环。

## 结果描述

完成本迭代后，用户（演示者）可以：

- 在独立设置页勾选料理手段（technique）与料理时间（time）偏好（0 成员，无成员区）
- 将当前组合保存为方案；列出方案；调出方案自动填充勾选；编辑方案名称与勾选项；删除方案；标记/取消默认方案
- 从设置页进入结果页时，当前勾选偏好作为 `elements` 传入 `POST /api/decisions`，决策接口按此偏好返回菜谱
- 每次进入设置页不自动应用默认方案，由用户手动勾选或调出方案

## 衡量方式

- 设置 → 生成全流程可操作（勾选 → 保存/调出方案 → 生成 → 展示）
- 方案调出后偏好自动应用，无需重新勾选（验证"配置一次、决策前复用"）
- 决策请求携带当前偏好 elements（替换硬编码参数）
- 0 成员：设置页无成员区，不影响决策
