# Dependencies & Order / 依赖与顺序（DRAFT）

## 依赖关系

- 架构搭建线整体前置：T-A1（骨架）→ T-A2（接口契约）先于业务线
- T-C2（种子数据）→ T-I1（查询/详情 API 依赖数据可查）
- T-I1（查询/详情 API）→ T-Ag3（候选筛选依赖数据接口）
- T-Ag1（基座：反向调用 + 超时）→ T-Ag2 / T-Ag3 / T-Ag4（Agent 决策依赖基座）
- T-Ag2 → T-Ag3 → T-Ag4（推荐方向 → 筛选迭代 → 排序返回，串行）
- T-Ag4（最终结果）→ T-I2（决策 API 依赖 Agent 结果组装）
- T-I2（结果组装格式）→ T-F5（前端渲染依赖返回格式）
- UI 线：T-U1 → T-U2（冻结）→ 前端实现
- 前端线：T-F1/T-F2 可先行；T-F5 依赖 T-U2 + T-I2；T-F6 依赖去重参数契约（T-A2/T-I2）

## 建议执行顺序

1. T-A1 骨架（双服务 + docker + 反向调用验证）→ T-A2 接口契约 + 数据模型
2. T-U1 线框 + T-C2 种子数据（并行）
3. T-I1 查询/详情 API → T-I2 决策 API
4. T-Ag1 基座 → T-Ag2 推荐方向 → T-Ag3 筛选迭代 → T-Ag4 排序返回
5. T-U2 结果稿冻结
6. T-F1 → T-F2 → T-F5 → T-F6 → T-F4 → T-F7 前端实现
7. 端到端联调（前端 → 接口服务 → Agent → 反向查询/详情 → 接口服务组装 → 前端）

## 关键路径

T-A1 → T-A2 → T-I1 → T-Ag1 → T-Ag2 → T-Ag3 → T-Ag4 → T-I2 → T-F5/T-F6 → 联调

（T-U 设计线与 T-C2 种子数据可在关键路径外并行）

## 阻塞项

- 无外部依赖（本地运行、docker 同机、种子数据、单人开发）
- 反向调用通道需在 T-A1 骨架内先行验证（避免联调阶段阻塞）
