# DoD & Review / 迭代级完成定义与评审（DRAFT）

## 迭代级 Definition of Done

- [ ] 决策页完整可操作：输入 → 生成 → 展示 → 追加，全流程可在本地运行演示
- [ ] Agent 规则化决策闭环可用：推荐方向 → 查询候选 → 详情确认 → 排序 → 返回
- [ ] 追加生成不产生重复菜谱（去重列表生效）
- [ ] 结果按固定格式 Markdown 展示，字段齐全（菜名/食材/调料/做法/时间/手段/标签）
- [ ] 无结果/超时有兜底，流程不中断
- [ ] docker-compose 同机启动接口服务 + Agent 服务，Agent 反向调用可用
- [ ] 完整流程 ≤ 3 次点击可得到结果
- [ ] 无已知 P0 缺陷
- [ ] 代码合入并在本地可启动
- [ ] Penpot 设计稿基线（决策页线框 + 结果 Markdown 模板稿 + 状态稿）已冻结并交付前端
- [ ] 估算校准：记录 1 点 ≈ ？实际工作量
- [ ] 技术选型验证结论已记录（骨架内验证后）

## 迭代评审方式

- 演示对象：用户（单人开发，自演示）
- 演示内容：从决策页勾选料理偏好 → 生成 1 道 → 查看固定格式 Markdown 结果 → 再来一个
- 衡量目标是否达成：
  - 核心价值："今天吃什么"的纠结是否显著降低（主观评估）
  - 客观指标：Agent 闭环可用、追加不重复、≤3 次点击出结果、无结果/超时兜底

## 评审待办（评审时问）

- 结果是否"能吃且倾向"（默认权重下，规则化决策质量）
- 追加生成是否有效缓解"不满意"
- 哪些点需要调整权重或交互
- 双服务 + Agent 反向调用的维护复杂度是否可接受（验证架构合理性）
