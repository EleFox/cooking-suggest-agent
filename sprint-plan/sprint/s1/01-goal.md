# Sprint Goal / 迭代目标（COMMITTED，2026-08-22 新架构版本）

## 一句话目标

跑通"决策+结果"核心闭环：决策前输入（料理偏好/时间）→ Agent 规则化决策（反向调用接口服务取数）→ 一键生成 1 道 → 固定格式 Markdown 展示 → 再来一个追加，验证"一次决策降低做饭纠结"的核心价值。

## 结果描述

完成本迭代后，用户（演示者）可以在决策页：

- 决策前勾选料理手段/时间偏好（0 成员，无成员区）
- 点击生成，接口服务透传决策输入给 Agent，Agent 结合偏好/时间判断推荐方向，反向调用查询 API 取候选摘要、详情 API 取 MD 全文确认，规则化筛选排序，返回 1 道菜谱
- 接口服务组装固定格式 Markdown，前端渲染展示（菜名/食材/调料/做法/时间/手段/标签）
- 点击"再来一个"，前端传入已展示菜谱 id 列表作为去重条件，追加获得不重复的新菜
- 候选为空或迭代达上限时，Agent 返回"无结果"，前端有兜底提示

## 衡量方式

- 决策页完整可操作（输入 → 生成 → 展示 → 追加）
- Agent 规则化决策闭环可用：推荐方向 → 查询候选 → 详情确认 → 排序 → 返回
- 追加生成不产生重复菜谱（去重列表生效）
- 无结果/超时有明确兜底，流程不中断
- 核心价值假设可验证：演示一次完整流程 ≤ 3 次点击
