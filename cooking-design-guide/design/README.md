# design/ — 设计文档

本目录是 AI 唯一允许产生和修改的设计产物目录。

## 目录结构

```
design/
├── README.md              # 本文件：设计文档入口
├── feature-index.md       # 功能最新设计索引
├── project/               # 项目级稳定设计
│   ├── service-overview.md
│   ├── persistence.md
│   └── integrations.md
├── agreement/             # 项目级稳定约定
│   └── api-conventions.md
└── sprints/               # 迭代设计
    ├── README.md
    └── S1/ S2/ ...        # 每个迭代的设计文档
```

## 项目级设计与迭代级设计的关系

- **项目级设计**（`project/`）：整个服务/项目的稳定技术设计，不随单次迭代变化。初始化后默认只读，修改需经用户明确确认。
- **接口约定**（`agreement/`）：接口层的稳定协议约定（如统一返回格式），修改需经用户明确确认。
- **迭代级设计**（`sprints/<Sx>/`）：某次迭代的具体设计。当前迭代可写，完成后进入只读。

后续迭代若修改历史功能，不在历史文档中改动，而是在当前迭代中产生新设计，并更新 `feature-index.md`。

## 文档修改规则

| 目标                            | 权限                         |
| ------------------------------- | ---------------------------- |
| `project/`                    | 初始化后只读；修改须用户确认 |
| `agreement/`                  | 只读；修改须用户确认         |
| 当前 `sprints/<Sx>/`          | 可写                         |
| 历史 `sprints/<Sx>/`          | 只读                         |
| `docs/`（需求、迭代需求、UI） | 只读                         |

## 如何定位某个功能的最新设计

1. 打开 `feature-index.md`。
2. 找到该功能对应的"最新设计文档"列。
3. 读取对应文档。

`feature-index.md` 是功能最新设计的唯一索引。

## 约束

- 本目录只存放设计文档，不存放详细业务设计之外的内容。
- 需求文档与 Penpot 数据位于 `docs/`，只读，仅作设计输入。
