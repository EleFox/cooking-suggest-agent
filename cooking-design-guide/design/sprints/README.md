# design/iterations/ — 迭代设计

本目录按迭代保存设计文档。每个迭代对应一个子目录 `Sx/`（如 `S1/`、`S2/`）。

## 目录结构

```
iterations/
├── README.md          # 本文件
└── S1/
    ├── api.md         # 接口设计
    ├── modules.md     # 模块设计
    └── business.md    # 业务设计
```

## 文件职责

| 文件 | 内容 |
|---|---|
| `api.md` | 新增/修改接口、请求参数、返回结构、错误、鉴权、权限、幂等、分页/排序、状态码、与业务逻辑的关系 |
| `modules.md` | 新增/修改模块、模块职责、依赖、类/服务职责、核心方法职责、模块边界、与现有模块的关系 |
| `business.md` | 正常/分支/异常流程、状态转换、业务规则、边界条件、并发、幂等、一致性、权限、数据处理顺序 |

## 读写规则

- **当前正在设计的迭代**（当前 `Sx/`）：可创建和修改。
- **已完成的历史迭代**（历史 `Sx/`）：**只读，禁止修改**。
- 后续迭代修改历史功能：在**当前迭代**中产生新设计，不修改历史文档。
- 当前迭代完成后，其设计文档进入只读状态。

## 定位最新设计

若需查看某功能的当前最新设计，通过 `design/feature-index.md` 定位，而非直接查看历史迭代。
