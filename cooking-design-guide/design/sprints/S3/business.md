# business.md — 业务设计（S3）

> S3 · 成员管理 + 成员启停 + 成员偏好联调决策 + 菜谱手动扩充/维护

## 正常流程

### 成员管理（T1）

1. 用户进入 `/members`：挂载调用 `GET /api/members`，渲染成员卡片列表（姓名 + 偏好食材/口味 + 食材禁忌摘要）
2. 点「新增成员」→ 进入 `/members/form`（成员表单页，新建模式）
3. 填写姓名；偏好食材 / 偏好口味 / 食材禁忌三个分区各自"输入 + 确认"添加条目（chips 带 × 可移除）
4. 点「保存」→ `POST /api/members` → 返回列表页，新成员出现在列表
5. 列表卡片点「编辑」→ 进入 `/members/form?id={id}`（同一表单页，编辑模式，回显姓名与三类条目）→ 保存 → `PUT /api/members`
6. 列表卡片点「删除」→ 确认 → `DELETE /api/members` → 刷新列表

### 设置页成员启停 → 决策（T2 + T3，主链路）

1. 用户进入 `/preferences`：挂载并行加载要素选项（technique + time，沿用 S2）与 `GET /api/members`
2. 成员区渲染成员行（姓名 + 开关），**默认全部启用**；0 成员时成员区空置，仅显示「管理成员」入口
3. 用户勾选料理手段 / 时间档位 / 生成数量（步进器，默认 1），按需关闭当天不吃饭成员的开关
4. 点「查看菜谱」→ 前端跳转 `/results?element_ids=...&member_ids=...&count=...`（0 勾选/0 成员省略对应参数）
5. 结果页挂载解析 query → 组装 `elements`：
   - 设置页勾选 → `relation_type="preference"`
   - 启用成员偏好 → `relation_type="preference"`；启用成员禁忌 → `relation_type="taboo"`
   - 合并规则：成员偏好/禁忌各自并集去重；与设置页勾选同 `element_id` 冲突时以设置页勾选为准；偏好×禁忌交叉冲突不处理（原样传入）
6. `POST /api/decisions`（`count` 取步进器值）→ 服务端 enrich 要素信息 + 翻译 `dedup_ids` 后转发 Agent → 展示卡片（`data` 卡片数组，由 `elements` 按 type 渲染）；「再来一道」沿用内存参数 + 追加 `dedup_ids`

### 菜谱新增（T4）

1. 结果页点「菜谱管理」入口 → `/recipes`；或成员/方案页同风格入口
2. 菜谱管理页点「新增菜谱」→ `/recipes/form`（菜谱表单页，新建模式）
3. 填写：名称；主要食材（输入 + 确认，chips 带 ×）；料理手段（chips 多选）；预估时间（步进器，分钟）；难度（chips 单选）；做法（多行文本，可空）
4. 点「保存」→ `POST /api/recipes` → 返回管理页，新菜出现在列表
5. 该菜进入菜谱池，后续决策可被推荐（要素标注完备时）

### 菜谱维护（T5）

1. 菜谱管理页挂载调用 `GET /api/recipes`（分页）；搜索栏输入关键字 → 按 `keyword` 重新查询
2. 整卡点击 → `/recipes/form?id={id}`（编辑模式）→ 挂载调 `GET /api/recipes/detail?ids={id}`（取数组首项）回显 → 保存 → `PUT /api/recipes`
3. 卡片右上 × → 确认 → `DELETE /api/recipes` → 刷新列表（物理删除，含种子菜谱）
4. 结果页卡片 × → 确认 → 同样调 `DELETE /api/recipes` → 从当前结果移除该卡片

## 分支 / 异常流程

| 场景 | 处理 |
|---|---|
| 0 成员 | 成员管理页空态引导（"还没有家庭成员"）；设置页成员区空置不阻塞；决策请求仅含设置页勾选 |
| 0 偏好 0 成员直接生成 | 允许；`elements=[]`，按无偏好返回 |
| 成员全部停用 | 允许；成员要素不展开，等价 0 成员 |
| 成员表单条目为空 | 允许（偏好/禁忌均可空）；姓名必填，前端禁用保存 + 后端 `422` |
| 自由文本重复添加 | 前端 chips 去重（同分区同 name 不重复添加）；后端按 `UNIQUE(type, name)` 完全匹配复用要素；`add` 已存在关联幂等忽略 |
| 同义不同字（土豆/马铃薯） | 本轮完全匹配，会产生两个要素；标签碎片化风险已知，未来大模型归并 |
| 同一要素既偏好又禁忌 | 成员表单允许保存；决策时不做处理，原样传 Agent 判断 |
| 编辑成员/菜谱时已被删除 | 按 id 定位失败 → 回退新建模式（成员）/ 返回列表（菜谱），提示资源不存在 |
| 菜谱无做法保存 | 合法；仅写表数据，`file_path=null`，`has_detail=false` |
| 编辑菜谱清空做法 | 删除原 MD 文件，`file_path` 置 null |
| 删除被结果页展示中的菜谱 | 结果页卡片随之移除；`dedup_ids` 含已删 id 无副作用（过滤条件） |
| 决策接口错误/超时 | 沿用 S1/S2：结果页错误提示，可重试 |
| Agent 未就绪 | 模拟返回仅按偏好匹配，**不做禁忌硬过滤**；禁忌生效演示依赖 Agent 联调（RK-01） |
| 成员/菜谱列表加载失败 | 页面展示错误提示，可重试 |

## 状态流转

### 成员管理页（`/members`）

```
挂载 ──GET──▶ 成员卡片列表（0 成员 → 空态引导）
   ├──新增──▶ /members/form（新建模式）──保存──POST──▶ 返回列表
   ├──编辑──▶ /members/form?id={id}（编辑模式）──保存──PUT──▶ 返回列表
   └──删除──▶ 确认 ──DELETE──▶ 刷新列表
```

### 设置页（`/preferences`，在 S2 基础上扩展）

```
挂载(空勾选, 成员默认全启用) ──查看菜谱──▶ /results?element_ids&member_ids&count
   ├──成员开关──▶ 内存态切换（不持久化）
   ├──管理成员──▶ /members
   ├──保存方案──▶ （沿用 S2，方案不含成员/数量）
   └──生成数量步进器──▶ 内存态（默认 1）
```

### 菜谱管理页（`/recipes`）

```
挂载 ──GET(分页)──▶ 菜谱卡片列表
   ├──搜索──▶ keyword 重新查询
   ├──新增──▶ /recipes/form（新建模式）──保存──POST──▶ 返回列表
   ├──整卡点击──▶ /recipes/form?id={id}（编辑模式）──保存──PUT──▶ 返回列表
   └──× 删除──▶ 确认 ──DELETE──▶ 刷新列表
```

## 业务规则与边界

- **表单页复用**：成员表单与菜谱表单新建/编辑共用同一路由与组件（`/members/form` / `/recipes/form`，query `id` 区分模式），不拆分独立页面
- **成员启停不持久化**：`t_member` 无 `enabled` 字段；启停为决策前临时勾选，每次进入设置页默认全部启用
- **成员要素合并规则**：偏好并集/禁忌并集按 `element_id` 去重；设置页勾选优先于成员要素；偏好×禁忌交叉冲突交 Agent
- **relation_type 语义**：`preference` 偏好（正向）、`taboo` 禁忌（硬排除）；设置页勾选与成员偏好恒 `preference`；`taboo` 仅来自成员禁忌（取值与 `t_member_element.relation_type` 一致）
- **决策预处理**：服务端转发 Agent 前，将 `elements` 按 `element_id` 补全为 `{id, type, name, sort_order, relation_type}`，并将 `dedup_ids` 复用批量详情逻辑翻译为完整菜谱（`{id, name, elements, detail}`，含正文，不存在则忽略）
- **要素统一数组契约**：成员/菜谱的要素参数一律为 `{name, type}` 数组（创建）与 `{name, type, id, operate}` 增量数组（更新）；新增要素类型不改变接口字段，支撑要素扩展
- **要素 resolve-or-create**：按 `UNIQUE(type, name)` 完全匹配，存在复用、不存在新建；要素只增不删
- **增量更新语义**：更新仅携带变更项（`add` / `remove` / `edit`），未变更关联不传输；空数组 = 无变更（非清空）；`edit` 等价 `remove` + `add` 的单条表达（当前 UI 仅产生 add/remove）
- **UI 类型映射**：成员偏好食材=`ingredient`、偏好口味=`taste`、食材禁忌=`ingredient`；菜谱食材=`ingredient`、手段=`technique`、难度=`difficulty`、时间=`time`（分钟数 name）
- **菜谱单值约束**：`time` / `difficulty` 类型要素每菜谱至多 1 个（创建与更新应用后均校验，违反 `422`）
- **菜谱全池可管**：不区分手动/种子来源，全部可编辑、可物理删除
- **做法与 MD 文件**：做法非空 → 生成/更新 MD 文件；做法为空 → 仅表数据；删除菜谱物理移除文件
- **时间语义**：菜谱时间为具体分钟数（步进器录入）；偏好时间档位区间匹配规则沿用 S2（菜谱值 ≤ 档位值）
- **生成数量**：步进器启用（默认 1），`count` 随决策请求生效；修订 S2 "固定 1" 约束
- **方案与成员解耦**：料理偏好方案（S2）仅缓存手段/时间勾选，不含成员启停与生成数量

## 一致性 / 幂等

- 成员/菜谱 CRUD：单用户本地应用，低并发；写操作（要素 resolve-or-create、增量 operate 应用、MD 文件写入）在单事务/单逻辑单元内完成，避免半写状态
- 增量 operate 幂等：`add` 已存在关联忽略、`remove` 不存在关联忽略、`edit` 解析结果相同为 no-op
- 成员删除：删成员行 + 级联关联行单事务；不触碰 `t_element`
- 菜谱删除：表行 + 关联 + MD 文件物理删除；文件缺失不视为错误（容忍已缺文件）
- 决策接口只读 + 模拟返回，无持久化副作用，天然幂等
- `GET /api/members` / `GET /api/recipes` / `GET /api/recipes/detail` 只读，幂等
- 重复提交由前端禁用按钮控制（沿用既有约定，不引入幂等键）
