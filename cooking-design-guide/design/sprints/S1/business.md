# business.md — 业务设计（S1）

> S1 · 菜谱卡片列表页 + "再来一道"

## 正常流程

### 首次生成

1. 页面挂载 → 前端自动发起决策请求（`count=1`，`dedup_ids=[]`，`elements` 取硬编码参数）
2. 接口服务按请求返回 1 道菜谱卡片（本轮为种子菜谱模拟结果）
3. 前端渲染第一张卡片，将该菜谱 id 记入去重列表

### 再来一道

1. 用户点击"再来一道" → 前端携带去重列表（已展示全部 id）再次请求（`count=1`）
2. 接口服务过滤去重列表，返回不重复的新菜谱卡片
3. 前端追加渲染新卡片，id 追加进去重列表
4. 可不断叠加

## 分支 / 异常流程

| 场景 | 处理 |
|---|---|
| 候选池耗尽 / 无合适菜谱 | 接口返回 `data.data=[]` + `data.message="没有合适的菜了"`，前端展示提示，不新增卡片 |
| 服务异常 / 超时 | 接口返回错误（`code≠200`），前端展示错误提示；"再来一道"按钮保留，点击即重试（不自动重试） |
| 请求进行中用户再点"再来一道" | 按钮禁用，忽略重复触发 |

## 状态流转

```
挂载 ──自动请求──▶ 加载中 ──成功──▶ 展示卡片列表 ──再来一道──▶ 加载中 ──▶ 追加卡片
                          │                              │
                          ├──无结果──▶ 展示提示(不新增)     └──错误──▶ 展示错误提示(可重试)
                          └──错误──▶ 展示错误提示(可重试)
```

## 业务规则与边界

- **去重**：去重列表由前端维护并随请求传入；接口服务保证返回不与已展示菜谱重复
- **生成数量**：本轮固定 1 道（接口保留 `count` 参数）
- **卡片删除（×）**：前端本地移除卡片，无接口；删除是否影响去重列表由后续迭代确定
- **卡片点击**：本轮无行为（详情页后续迭代）
- **决策参数**：硬编码于前端常量，本轮无用户输入界面
- **模拟返回**：Agent（黑盒）未就绪，决策接口本轮返回固定/种子菜谱；透传契约不变，Agent 就绪后接入

## 一致性 / 幂等

- 决策接口只读查询，无持久化副作用，重复调用不产生脏数据
- 同一 `dedup_ids` 重复请求返回相同结果（幂等）
- 前端无并发写操作（单用户本地）
