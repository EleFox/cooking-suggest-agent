# business.md — 业务设计（S2）

> S2 · 料理偏好设置页 + 方案缓存 + 决策接口对接

## 正常流程

### 设置 → 生成（主链路）

1. 用户进入 `/preferences`：挂载加载要素选项（technique + time 档位），勾选为空
2. 用户勾选料理手段（可多选）与料理时间档位（单选）
3. 点「生成」→ 前端跳转 `/results?element_ids=...`（0 勾选则省略参数）
4. 结果页挂载读取 `element_ids` → 组装 `elements`（`sentiment=1`）→ `POST /api/decisions`
5. 决策接口按偏好返回菜谱卡片，结果页沿用 S1 卡片展示与「再来一道」

### 保存方案（新建）

1. 设置页已勾选一组偏好（也可空勾选存空方案）
2. 点「保存」→ 输入方案名 → `POST /api/preference-schemes`
3. 方案持久化（`t_preference_scheme` + `t_scheme_element`），出现在方案列表

### 调出方案

1. 方案页点「调出」→ 跳转 `/preferences?scheme_id={id}`
2. 设置页填充该方案勾选（不自动应用，用户可继续修改）
3. 修改后点「保存」→ **新建**方案；点「生成」→ 按当前勾选进结果页

### 编辑方案

1. 方案页点「编辑」→ 跳转 `/preferences?edit_scheme_id={id}`
2. 设置页填充勾选 + 方案名预填（编辑模式）
3. 修改名称/勾选后点「保存」→ `PUT` **更新原方案**（不新建）

### 删除 / 默认标记

1. 方案页点「删除」→ 确认 → `DELETE` → 列表刷新；删除默认方案后系统无默认
2. 方案页切换默认开关 → `PUT`（`is_default=1` 时服务端事务互斥，其余方案置 0）

## 分支 / 异常流程

| 场景 | 处理 |
|---|---|
| 0 偏好直接生成 | 允许；`elements=[]`，决策接口按无偏好返回 |
| 0 成员 | 设置页无成员区；决策请求仅携带手段/时间偏好，无成员参数，流程正常 |
| 方案列表为空 | 方案页空态提示；设置页仍可正常勾选与生成 |
| 保存时方案名为空 | 前端禁用保存 / 后端 `422` 校验 |
| 要素选项加载失败 | 设置页展示错误提示，重试加载 |
| 决策接口错误/超时 | 沿用 S1：结果页错误提示，可重试 |
| 调出/编辑时方案已被删除 | 设置页按 id 定位不到 → 回退为空勾选（新建模式） |
| 方案重名 | 允许，无冲突处理 |

## 状态流转

### 设置页

```
挂载(空勾选) ──生成──▶ /results?element_ids=...
   │
   ├──保存(新建)──▶ 输入方案名 ──POST──▶ 成功/错误提示
   │
   └──(从方案页带 scheme_id/edit_scheme_id 进入)──▶ 填充勾选
        ├──编辑模式: 改后保存 ──PUT──▶ 更新原方案
        └──调出模式: 改后保存 ──POST──▶ 新建方案
```

### 方案页

```
挂载 ──GET 列表──▶ 方案卡片列表
   ├──默认开关──▶ PUT(is_default) ──▶ 刷新列表
   ├──调出──────▶ /preferences?scheme_id={id}
   ├──编辑──────▶ /preferences?edit_scheme_id={id}
   └──删除──────▶ 确认 ──DELETE──▶ 刷新列表
```

## 业务规则与边界

- **时间偏好**：档位固定 15 / 30 / 60 分钟；匹配为区间（菜谱 `time` 要素值 `<=` 档位值），非相等
- **手段偏好**：`technique` 要素（种子：煎/炒/凉拌/油炸/蒸/炖/煮/烤），相等匹配
- **sentiment**：设置页仅正向勾选，恒 `1`（无厌恶表达）
- **设置页不自动应用默认方案**：每次进入空勾选，由用户手动勾选或调出/编辑方案
- **默认方案唯一性**：服务端事务保证 `is_default` 全局唯一
- **方案重名允许**：`name` 无唯一约束
- **0 偏好 / 0 成员**：均不影响决策主流程
- **调出 vs 编辑**：调出后保存为新建（不改原方案）；编辑后保存更新原方案

## 一致性 / 幂等

- 方案 CRUD：单用户本地应用，低并发；写操作（创建/更新/删除/默认互斥）在单事务内完成，避免半写状态
- `t_scheme_element` 随方案更新先删后插（或增量同步）与方案行更新同事务，保证勾选一致
- 决策接口只读查询 + 模拟返回，无持久化副作用，天然幂等
- `GET /api/elements` / 方案列表只读，幂等
