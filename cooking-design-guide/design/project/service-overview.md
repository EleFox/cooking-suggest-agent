# service-overview.md — 服务概览

> 描述整个服务/项目的**稳定技术设计**，不随单次迭代变化。
> 单用户本地应用，前后端分离；核心决策由外部 Agent 服务承担，本项目负责交互、数据管理与决策前置。

## 服务职责

本服务是"多因素菜谱决策"应用的**前端 + 后端接口服务**，职责：

- 维护决策输入数据：成员偏好/禁忌、料理偏好方案、决策因素权重、使用记录
- 提供菜谱读取能力：条件查询（关键字/分页/去重排除）、要素批量详情读取、摘要生成
- 对接外部 Agent 决策服务：透传决策输入、接收最终决策结果
- 将决策结果组装为卡片 JSON（elements 数组）供前端渲染
- 记录决策日志（使用记录，P2）

**不承担**：核心决策逻辑（软排序、知识比对、时令/健康判断）由外部 Agent 服务负责。

## 系统边界

**属于本系统**：
- 前端应用（收集决策输入、渲染结果、兜底显示）
- 后端接口服务（数据管理、菜谱读取、Agent 对接、结果组装）
- SQLite + 菜谱 MD 文件的本地持久化

**不属于本系统**：
- 决策引擎核心（Agent 决策服务）：知识库查询、推荐方向、候选筛选确认、最终排序
- Agent 服务的内部实现与知识库内容
- 菜谱种子数据的批量导入与维护（由固定脚本执行，非本系统运行职责）
- 时令/健康知识管理（Agent 侧）
- 账号/权限体系（单用户，无此需求）

**系统形态**：
- 单用户，无账号体系
- 前端服务与后端接口服务为两个容器，与 Agent 服务同机部署（docker-compose 编排）
- Agent 反向调用本系统菜谱查询/详情 API（同机可达）

## 核心模块

| 模块 | 职责 |
|---|---|
| 成员管理 | 成员 CRUD + 偏好/禁忌关联维护（`t_member` / `t_member_element`） |
| 料理偏好方案 | 方案的保存/读取/应用（含默认方案）、决策输入组装（`t_preference_scheme` / `t_scheme_element`） |
| 菜谱读取 | 菜谱查询（关键字/分页/去重排除）、要素批量详情读取、摘要生成（`t_recipe` / `t_recipe_element` + `recipes/*.md`） |
| Agent 决策对接 | 决策请求组装、透传 Agent、接收结果、失败/超时降级处理 |
| 权重设置 | 决策因素权重读写（`t_weight_setting`） |
| 结果组装 | 将 Agent 返回的决策结果组装为卡片 JSON（elements 数组），交前端渲染 |
| 使用记录 | 决策日志记录与查询（P2，`t_usage_record` / `t_usage_record_recipe`） |

## 核心领域对象

| 领域对象 | 说明 | 关系 |
|---|---|---|
| 成员 Member | 家庭成员，含偏好/禁忌集合 | 关联烹饪要素 |
| 烹饪要素 Element | 食材/料理手段/料理时间/过敏原/口味/烹饪难度 的字典 | 被成员、方案、菜谱关联 |
| 料理偏好方案 PreferenceScheme | 可复用的料理偏好组合（默认方案） | 关联烹饪要素 |
| 菜谱 Recipe | 主数据（`t_recipe`）+ 可选 MD 详情文件 | 关联烹饪要素，关联详情文件 |
| 决策上下文 DecisionContext | 一次决策的全部输入（偏好、禁忌、权重、去重列表等） | 透传给 Agent |
| 使用记录 UsageRecord | 决策历史日志 | 关联被选菜谱 |

## 模块之间关系

```
前端应用
  │  ① 决策输入 / ② 结果卡片 JSON
  ▼
后端接口服务
  ├── 成员管理
  ├── 料理偏好方案
  ├── 权重设置
  ├── 菜谱读取 ──────────────── Agent 反向调用（查询/详情）
  ├── Agent 决策对接 ────────── 透传决策上下文 → Agent
  ├── 结果组装
  └── 使用记录
```

- **Agent 决策对接**依赖：成员管理、料理偏好方案、权重设置（读取决策输入）与菜谱读取（供 Agent 反向查询）
- **结果组装**依赖 Agent 决策对接的返回结果与菜谱读取的详情数据
- **使用记录**依赖决策上下文与结果（P2）

## 与数据层关系

- 成员管理 → 读写 `t_member` / `t_member_element`
- 料理偏好方案 → 读写 `t_preference_scheme` / `t_scheme_element`
- 权重设置 → 读写 `t_weight_setting`
- 菜谱读取 → 只读 `t_recipe` / `t_recipe_element` + 读 `recipes/*.md`
- 使用记录 → 读写 `t_usage_record` / `t_usage_record_recipe`（P2）
- 详细数据设计见 `persistence.md`

## 与外部服务关系

- **Agent 决策服务**（唯一外部服务）：
  - 本系统 → Agent：透传决策上下文（同步，方案 C，Agent 端自限时限）
  - Agent → 本系统：反向调用菜谱查询 API（返回 elements 摘要）与菜谱详情 API（批量返回要素 + 做法文本），筛选确认后回传最终结果
  - 详细协议见 `integrations.md`

## 核心业务能力

- 成员偏好/禁忌管理（配置一次、决策前可启停）
- 料理偏好方案保存/复用（默认方案联动决策页）
- 菜谱条件查询（关键字 + 分页 + 去重排除 + 要素摘要）、要素批量详情读取（含做法正文）
- 决策请求转发与结果接收（含失败/超时降级）
- 决策结果卡片组装（elements 数组）
- 决策因素权重设置

## 重要约束

1. 本项目**不实现决策核心逻辑**，软排序/知识比对/最终筛选均在 Agent 服务
2. 菜谱查询 API 提供关键字、分页与 `exclude_recipe_ids` 去重；禁忌硬过滤由 Agent 端自行处理
3. 权重作为决策参数随首次请求传给 Agent，由 Agent 判断
4. 排序相关度设计**搁置**（暂不做，数据可靠近返回但无显式相关度排序）
5. 死循环控制由 Agent 端负责；本系统仅处理"Agent 返回无结果"
6. 去重列表由前端传入菜谱 id，服务端翻译为完整菜谱后随决策上下文给 Agent
7. 同步交互 + 超时兜底：不引入异步任务/轮询
8. 菜谱数据由本系统维护（用户 CRUD + 种子只读导入脚本）
