# opencode — 项目级规则

本项目通过 opencode 进行 AI 技术设计引导。以下规则在每次会话中都必须遵守。

## 绝对红线

- 本项目**只产生和修改设计文档**（`design/` 目录）。
- **禁止读取**任何实际业务代码（如 `cooking-agent`、`cooking-web-service`）。
- **禁止修改**任何实际业务代码。
- **禁止生成**任何业务代码。
- **禁止要求**用户将业务代码放入本项目。
- **禁止修改**需求文档（`docs/requirements/`、`docs/iterations/`）。
- 本项目最终产物只有设计相关文档。

## 文档修改权限速查

| 目标 | 行为 |
|---|---|
| `design/project/` | 初始化后可写；之后**只读**，修改须用户确认 |
| `design/iterations/<当前Sx>/` | 可写 |
| `design/iterations/<历史Sx>/` | **只读** |
| `docs/requirements/`、`docs/iterations/`、`docs/ui/` | **只读** |

## 设计工作方式

1. 设计讨论优先于直接生成文档。
2. 一次只围绕当前**最重要**的一个设计疑点讨论。
3. 主动检查：异常流程、边界条件、状态流转、并发、幂等、一致性、权限、职责边界、数据模型与业务匹配、API 与业务匹配、UI 与 API/业务匹配、设计冲突、信息缺失。
4. 当前设计无关键疑点、剩余问题不影响实现、或用户明确足够时，结束讨论并整理文档。

## 历史迭代不可变

- 已完成迭代设计禁止修改。
- 修改历史功能：先查 `design/feature-index.md` 定位最新设计 → 读取对应文档 → 在**当前迭代**描述新设计 → 完成后更新 `feature-index.md`。

## 项目级设计修改

- `design/project/` 需修改时不得直接改。
- 先向用户说明：当前设计、为何无法在原设计下完成、建议如何修改、影响哪些项目级与当前迭代设计。
- **必须获得用户明确确认后才修改**。

## 入口

- 阅读设计文档入口：`design/README.md`
- 功能最新设计索引：`design/feature-index.md`
