# AGENTS.md — AI 技术设计引导项目

本项目是一个独立于实际业务代码的 **AI 技术设计引导项目**。本项目不包含、不读取、不修改任何业务代码，只负责通过 AI 对话引导用户完成技术设计，并维护设计文档。

## 项目核心约束（必须遵守）

1. **禁止读取任何实际业务代码**（不读取 `cooking-agent`、`cooking-web-service` 等实际项目）。
2. **禁止修改任何实际业务代码**。
3. **禁止生成业务代码**。
4. **禁止要求用户将业务代码放入本项目**。
5. **本项目最终产物只有设计相关文档**。

## 文档修改权限

| 目录/文件                            | 权限                                                                   |
| ------------------------------------ | ---------------------------------------------------------------------- |
| `design/`                          | 设计产物唯一允许 AI 产生和修改的目录                                   |
| `design/project/`（项目级设计）    | 初始化后可创建；初始化完成后**默认只读**；修改必须经用户明确确认 |
| `design/agreement/`（项目约定）    | 稳定约定；修改必须经用户明确确认                                       |
| `design/sprints/<Sx>/`（当前迭代） | 可创建和修改                                                           |
| `design/sprints/<Sx>/`（历史迭代） | **只读，禁止修改**                                               |
| `@requirements`（需求文档）        | **只读，禁止修改**                                               |
| `@sprints`（迭代需求文档）         | **只读，禁止修改**                                               |
| `@ui-docs`（Penpot 数据）          | **只读**，仅作 UI/交互设计参考                                   |

## 设计工作方式

- **设计讨论优先于直接生成文档**。一次只围绕当前最重要的一个设计疑点进行讨论，根据用户回答继续推导，而不是一次抛出大量问题。
- AI 应**主动检查**：异常流程、边界条件、状态流转、并发、幂等、一致性、权限、职责边界、数据模型与业务逻辑匹配、API 与业务逻辑匹配、UI 与 API/业务匹配、设计冲突、信息缺失。
- 当当前设计已无关键疑点、剩余问题不影响当前实现，或用户明确表示足够时，结束讨论并整理文档。

## 历史迭代不可变原则

- `design/sprints/S1/`、`S2/`… 已完成的迭代设计**禁止修改**。
- 后续迭代若需修改历史功能：先查 `design/feature-index.md` 找到该功能最新设计，读取对应历史文档，再**在当**前迭代中描述新设计，完成后更新 `design/feature-index.md`。
- 历史文档 = 历史设计记录；最新迭代 = 当前有效修改；`feature-index.md` = 功能最新设计索引。

## 项目级设计修改规则

若 `design/project/` 下的设计必须变化，**不得直接修改**。先向用户说明：当前设计是什么、当前迭代为何无法在原设计下完成、建议如何修改、会影响哪些项目级设计与当前迭代设计。**必须获得用户明确确认后才修改**。第一次初始化项目级设计时例外，可直接依据已有资料建立初始设计。

## feature-index.md

- 是"某个功能当前最新设计在哪里"的索引，不是详细设计。
- 每个功能只记录当前最新有效设计。
- 处理"修改已有功能"时，首先通过它定位最新设计，再读取对应文档。

## 设计阶段

每次迭代设计遵循：`Prepare → Analyze → Discuss → Draft → Review → Confirm → Finalize`。

## 输入资料

- `@requirements`：完整需求文档（只读）
- `@sprints`：迭代需求文档（只读）
- `@ui-docs`：Penpot UI 结构化数据（只读）

## 文档阅读导览

- `@requirements`为需求文档，在阅读前应该先阅读 `99-summary.md`文件获取需求文档的概览和文档导读
- `@sprints`为迭代文档，S+编号对应迭代轮次，讨论时需要确定讨论的迭代轮次，如果用户没有提供请先咨询
- `@sprints`的 `sprint/S*`中，应该优先阅读  `99-summary.md`文件获取当前迭代的基础信息和文档导读
- `@ui-docs`为ui设计资源，查看时应该优先阅读 `README.md`文件获取解读方式，该UI设计仅供参考页面设计
